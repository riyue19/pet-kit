# 功能实现说明

> 从 CLAUDE.md 移出，按需阅读：改哪块功能就看哪一条，不要整篇读。内容为各里程碑的实现细节、协议、配置项与接口。

- 后端配置：`config/backend.yaml`（端口、LLM 多套配置、用途指定、asr 语音识别、tts 语音合成）。API Key 不在文件里，存 Windows 凭据管理器（keyring 服务名 `pet-kit/llm`，用户名 = 配置名）。
- 网络代理：`network.proxy`（`direct` 默认 / `system` / 代理 URL，改后重启后端）。默认直连，后端的 LLM、MiniMax、天气三处 HTTP 客户端都不读系统代理，避免代理软件关闭或崩溃但系统代理标志还在时全部立刻连不上。实现在 `backend/core/net.py`，新增 HTTP 客户端必须用 `net.make_client()`（openai 用 `DefaultAsyncHttpxClient(**net.client_kwargs())`）。
- 鉴权：后端每次启动生成随机令牌，和端口一起写入 `%LOCALAPPDATA%/pet-kit/backend.json`；Electron 主进程读取后代理控制台请求（路径白名单见 `frontend/src/shared/backend.ts`），令牌不进渲染层。
- 控制台 LLM 页 / 识图页需要后端在运行，否则显示"后端未运行"并提供重试。
- 人设：`config/persona.yaml`（名字、system prompt、历史轮数、回复字数上限）；点击反应：`config/reactions.yaml`（头/身体台词、表情/动作标签、交给 LLM 的概率、冷却）。两者每次事件重新读取，改完无需重启。
- 表情包：图片在 `data/stickers/`（不进 git），索引 `config/stickers.yaml`（id / file / name 备注名 / enabled），控制台「表情包」页（`pages/StickersPage.vue`，内含 `components/StickersCard.vue`）导入（PNG/JPG/GIF/WebP，按文件内容识别，单张 ≤ 2 MB，最多 60 张）、改备注名、停用、删除，改动立即生效。桌宠在 `hello` / `labels` 消息的 `labels.stickers` 里把启用的备注名告诉后端；有表情包时提示词多一段「表情包」（`TEMPLATES["stickers"]`，可在提示词页整段修改），回复 JSON 多一个可选字段 `sticker`（备注名或 null，只有桌宠报上来的名字才保留）。主进程按备注名读出图片（data URL）附在 `AgentOutput.stickerUrl` 上，桌宠气泡在文字下面显示。图片本身从不发给模型，也不写进聊天记录。实现：`frontend/src/main/stickers.ts`、`frontend/src/shared/stickers.ts`。
- 表情/动作映射：`config/models/<模型目录名>.yaml`，标签（`^[a-z][a-z0-9_]{0,31}$`）→ 模型自带的表情名 / 动作组+序号，以及表情保持秒数。动作可带可选的 `expression`（配套表情：模型自带表情名，播该动作时显示、动作结束后收起，用于「动作只驱动道具、道具靠表情才显示」的模型，如 VTube Studio 导出的抛硬币；此时本次回复的脸部表情让位给它）。表情保持到时后会把库里的「当前表情」一并清掉，否则同一表情连续第二次不生效。动作播完后所有参数在 0.5 秒内平滑回到默认值（没有待机动作组的模型否则会停在动作最后一帧，比如睡觉动作结束时一直歪着头）。动作可带可选的 `loop: true`（循环：播完自动重播，直到主人点它 / 打字 / 开口说话、桌宠说话、或播了别的动作；控制台试播用「停止当前动作」结束）。空闲动作：`proactive.idle_action*`（「感知」页「空闲动作」卡片）——距主人上次和桌宠互动（`ProactiveGate.last_user`，不看键鼠空闲时间）超过 `idle_action_minutes` 时，`Scheduler.idle_action()` 发出 `timer.idle {kind: "action", motions, expressions}`，`Dispatcher._idle_action` 在规则层从当前模型拥有的标签里各随机挑一个下发（不调 LLM、不占主动说话次数、不受 `proactive.enabled` 影响，标签都不存在时什么也不做），之后每隔同样时间重复。`GET /api/screen` 多返回 `labels`（当前模型标签）供下拉用。试播的动作没播出来时前端日志有 `[actions] 动作 … 没有播放`。控制台模型页「表情与动作」编辑；LLM 只能用这里定义的标签。
- 桌宠 WS：Electron 主进程连 `ws://127.0.0.1:<port>/ws/pet`，首条消息 `{type:"hello", token, labels}`（失败关闭码 4401）。客户端发：`labels` / `event`（仅 `user.text`、`pet.interaction`、`hotkey.pressed`）/ `playback{playing}` / `stop` / `ptt{id}`（按住说话）/ 二进制麦克风帧（16kHz 单声道 16bit LE PCM，仅在 `mic.listen` 为真时）。服务端发：`ready` / `mic{listen}` / `status{thinking}` / `output` / `hearing{active}` / `heard{text}` / `interrupt` / `audio_start{id,sample_rate}` + 二进制 TTS PCM + `audio_end{id,error?}` / `error`。协议的权威说明见 `backend/api/pet_ws.py` 的文档字符串。后端断开后主进程每 2→15 秒重连，桌宠输入框提示"后端未连接"，麦克风自动关闭。
- `pet.interaction`：桌宠上短按（<5px、<500ms）发送 `{kind:"click", area:"head"|"body"}`，先走规则层（reactions.yaml），按概率才交给 LLM。
- 语音（M3）：控制台「语音」页。收音开关（`asr.listen`）开了就一直收音，关了桌宠就不打开麦克风；只有 Silero VAD 判断有人说话，才把这段音频交给本地 SenseVoice 识别，识别结果作为 `voice.utterance` 事件走和文字聊天相同的流程。回复由 MiniMax 国内站（`https://api.minimax.cn`，只需要 Bearer Key，不需要 Group ID）流式合成 24kHz PCM，在桌宠窗口播放，口型跟随播放音量（模型 LipSync 参数，默认 `ParamMouthOpenY`）。`asr.barge_in`（默认关）：关闭时桌宠把当前这句说完，期间识别到的话照常交给 LLM，回复排队（最多 3 条），等桌宠窗口报告播放结束再显示和朗读；开启时用户开口超过 `asr.barge_in_seconds` 就打断播放并清空队列。回声靠两层处理：Chromium 回声消除，加上后端回声过滤（播放中或刚播完时，如果识别出的文字大部分和正在说的话重合就丢弃）。括号里的动作描写不朗读。MiniMax Key 存 Windows 凭据管理器（服务名 `pet-kit/tts`，用户名 `minimax`）。输入框右侧的小圆点是收音指示：暗绿表示在听，亮绿表示听到有人说话。
- 日志（M4）：后端 `%LOCALAPPDATA%/pet-kit/logs/backend.jsonl`（每天零点轮转，保留 14 天），前端 `frontend-YYYY-MM-DD.jsonl`（Electron 主进程 + 桌宠窗口 + 控制台窗口的 warning/error、崩溃）。每行 JSON 字段：`ts level logger file line func msg event_id exc`（前端每行另有 `seq`）。前端开了 sourcemap，主进程日志的 file:line 指向 `src/main/*.ts`。后端实现在 `backend/core/logs.py`，`EventBus` 处理事件时会设置 `current_event`，所以同一次对话的所有日志（LLM、TTS、语音）都带同一个 `event_id`；密钥由 `RedactingFilter` 打码。前端实现在 `frontend/src/main/logger.ts`（会接管主进程的 `console.warn/error`）。控制台「日志」页：后端日志从 `GET /api/logs?after&level&logger&event_id&q&limit` 读内存里最近 3000 条，前端日志走 `petConsole.frontendLogs`；点 event_id 可以只看这一次对话。启动器重定向的 `backend.log` / `frontend.log` 是原始 stdout，排错优先看 jsonl。
- 事件（M4）：控制台「事件」页 `GET /api/events?after&type&limit`（最近 500 个事件，带处理结果），`POST /api/events {type,payload}` 可以注入 `user.text` / `voice.utterance` / `pet.interaction`，走真实流程，会产生费用。人设页 `GET/PUT /api/persona` 写回 `config/persona.yaml`（保留注释）。
- 控制台代理路径白名单只允许 `/api/logs`、`/api/events` 带查询串（`withQuery()` 负责生成）。
- 记忆（M4.5）：`%LOCALAPPDATA%/pet-kit/memory.db`（SQLite，不进 git）。`messages` 存每一次交给 LLM 的问答（文字/语音/互动），永久保存；`memories` 存长期记忆（自动总结或手动添加，可置顶）。向量模型 bge-small-zh-v1.5 int8（`backend/models/embed/`，`scripts/fetch_models.py` 下载），在本地 CPU 上运行，单次检索约 3ms；模型缺失时照常保存聊天记录，只是不做语义检索，下载后再进控制台记忆页会自动加载并补算向量。每次回复的 system prompt = 人设 + 当前时间 + 【你记得的事】（置顶记忆 + 相似度 ≥ `memory.min_similarity` 的前 `recall_memories` 条记忆 + 前 `recall_messages` 条旧对话）+ 输出格式；最近 `persona.history_turns` 轮从数据库读取。累计 `memory.summarize_every_turns` 轮未总结的对话时，后台调用 LLM（`llm.roles.memory`，未设置则用 chat）输出 add/update/delete；模型只能修改自动总结出、未置顶的记忆（置顶和手动添加的以只读形式提供，且每次最多 新增 20 / 修改 5 / 删除 3 条，超出整批丢弃，防止对话里的指令被当真）。任何失败后 10 分钟内不重试。写入前用 `redact_sensitive` 打码：已知密钥、`密码/验证码是…`、24 位以上的类密钥串；启动时会预先登记所有已存的 Key。置顶记忆每次最多带 10 条 / 1000 字。实现：`backend/core/memory/{store,service,factory}.py`，接口：`backend/api/memory_routes.py`（`/api/memory`、`/api/memory/summarize`、`/api/memories`、`/api/history`、`/api/history/days`、`/api/history/delete`）。控制台「聊天记录」「记忆」页。
- 语言（M4.5 追加）：`asr.language` 默认 `zh`（`auto` 会把气声识别成 `お。` 之类）。`tts.speech_language` = `ja`/`en` 时，输出格式多一个 `speech` 字段（`AgentOutput.speech`）：气泡显示 `text`（中文），TTS 读 `speech`，MiniMax `language_boost` 跟着设置；聊天记录和记忆只存 `text`。记忆库是单文件（journal_mode=DELETE，没有 `-wal`），位置由 `memory.db_path` 决定（空 = `%LOCALAPPDATA%/pet-kit/memory.db`），在控制台修改时会移动数据库（目标已存在则直接改用目标）。控制台日志会过滤 Chromium 的 `ResizeObserver loop` 提示。
- 快捷键（M5）：`config/hotkeys.yaml`，由 Electron 主进程读写（`frontend/src/main/hotkeys.ts`，校验规则在 `frontend/src/shared/hotkeys.ts`，后端用 `backend/core/hotkeys.py` 的同构模型校验）。主进程用 `globalShortcut` 只注册声明过的组合（字母数字键必须带 Ctrl/Alt/Win，F1~F24 可以单独用），不监听其他按键。`builtin`（toggle_visible / toggle_mic / stop_speaking / open_console）在主进程本地执行；`reaction` / `llm` 发送 `hotkey.pressed {id}`（payload 只有 id），后端每次重新读取文件，经过冷却（`cooldown_seconds`）后：reaction 随机挑一句台词和模型里已有的表情/动作标签，llm 把 `prompt` 当作用户这句话交给 Agent（会记入聊天记录）。控制台「快捷键」页可以录制组合键（录制期间通过 `suspendHotkeys` 暂停全部快捷键，控制台关闭时自动恢复），保存后立即重新注册，并显示哪些组合因冲突没有注册成功。WS 新增客户端消息 `{type:"stop"}`：停止说话、清空朗读队列，并丢弃在此之前已经开始生成的回复。前后端都逐条校验 hotkeys.yaml，坏的一项只跳过这一项，其他照常生效（两边规则必须保持一致：未知字段忽略、超长截断、数字转成文本）；控制台每次打开都重新读取文件，有无效项时会警告，保存前需要确认（保存会删掉无效项）。交给 LLM 的快捷键冷却至少 3 秒，所有 LLM 快捷键之间还共用 3 秒冷却；主进程对同一个快捷键做 300ms 去抖；toggle_mic 上一次还没处理完时，新的按键直接忽略。
- 屏幕感知（M6）+ 看屏幕吐槽：三档——① `perception/screen.py` 每 `screen.poll_seconds` 秒用 Win32 读前台窗口（进程名、标题、是否全屏，免费）；② 对已看过的内容，冷却期后每 10 秒算一次 16×16 dHash（本地，只在内存），变化超过阈值才算「画面变了」；③ 只有 `perception/screen_watch.py` 发出 `screen.changed {app,title,fullscreen,reason}` 且 `core/screen_comment.py` 依次通过「开关 → 前台仍是这内容 → 隐私黑名单 → 全屏设置 → `core/proactive.py` 闸门（免打扰进程/标题、正在说话或思考、主人 `quiet_after_user_seconds` 内刚互动过、两次主动发言最小间隔、每小时上限）」后，才截当前窗口 JPEG（≤1280px，只在内存）交给 `llm.roles.vision`，由 `Agent.respond_screen` 决定说一两句或保持安静（text 为空）。频率三档见 `core/screen_config.py` 的 `CADENCES`。`config/privacy.yaml`：block_*（绝不截图、标题不进事件）、quiet_*（会议/录屏/直播免打扰），改动按 mtime 自动生效，文件写错时沿用上一次的名单。桌宠自身（electron.exe）的窗口永远忽略。`screen.allow_fullscreen` 默认 true，是用户明确选择的「玩游戏/看视频也吐槽」，与 4.4 的「全屏免打扰」有意不同；会议/录屏仍免打扰。控制台「感知」页：开关、频率、隐私名单、天气城市、当前状态、「5 秒后看一眼」（跳过频率限制，不绕过黑名单）。接口：`/api/screen`、`/api/screen/look`、`/api/screen/weather`。
- 环境信息：`core/environment.py`，每次回复的 system prompt 附带当前时间，以及 `environment.city` 的天气（Open-Meteo，免费、无 Key，不按 IP 定位；缓存 30 分钟，失败 5 分钟后重试，失败时沿用上次结果）。「北京 朝阳」这种写法：区县查不到就退回到前一个地名。
- 语音识别过滤：去掉标点后少于 `asr.min_chars`（默认 2）个字的结果，以及只有语气词（嗯/啊/哦…）的结果，直接丢弃，不触发对话。另外 5 个字以内的结果，录音短于 `asr.short_min_seconds`（默认 1.0 秒）也丢弃：实测「不是。」「这个我。」这类杂音碎片不到 1 秒，而真正说的话都在 1 秒以上；更长的句子不受这个时长限制。0 = 关闭这项检查。被丢弃的内容会记进日志（带录音时长）。
- 联网搜索：由模型自带的搜索完成（不接第三方搜索 API）。每套 LLM 配置的 `web_search` 决定怎么开启：`google_function`（tools=[googleSearch 函数]，new-api 类中转站会映射成 Gemini Google 搜索）/ `openai_options`（web_search_options）/ `off`；`llm.web_search` 是总开关。开启后每次聊天都附带搜索工具和一句「实时信息先搜再答」的规则，由模型自己决定搜不搜（实测闲聊不搜、约 5 秒；搜索约 15 秒，新闻类大问题可能超过 1 分钟）；问题命中 `core/agent.py` 的 `FRESH_INFO`（最新/新闻/多少钱/比分/查一下…）时，还会在这句话后面追加「请先联网搜索」，防止模型偷懒。看屏幕永远不搜索。日志里会记「模型联网搜索了，引用来源 N 条」（来自响应的 annotations）。旧版控制台保存 LLM 页时如果不带 web_search 字段，后端会保留原值。
- M6 审查后的加固：截图用 PrintWindow 取窗口自己的内容（压在它上面的密码弹窗、通知不会被截进去）；窗口画不出来时（全黑）才改为截屏幕区域，而且只有上方没有黑名单窗口时才截；截图前后都会核对前台窗口没变。进程名读不出来时按隐私窗口处理（fail closed）。会议/录屏/直播的免打扰改为检查所有可见窗口（含最小化），不只看前台。闸门按「看了几次」计费（不管说没说），同一时间只看一次，调用失败后退避 5 分钟；在看的过程中主人开口了，这句吐槽就不说了。「看一眼」只跳过频率限制和「同一内容」检查，总开关、黑名单、免打扰、正在忙这些都照常生效。标题里的数字会归一化（计时、进度、未读数变化不算新内容），桌面和任务栏忽略不看。一键全关：托盘「关闭全部感知」和控制台左上角按钮 → `POST /api/privacy/off`（关麦克风和屏幕感知；M9 的摄像头也要加进来）。
- 主动对话（M7）：`core/scheduler.py` 每 30 秒做一次廉价检查，符合条件时发出 `timer.idle {kind, situation}`，由 `Dispatcher` 交给 `Agent.respond_proactive`（`llm.roles.chat`，不截图、不联网搜索，最多带 4 轮历史；text 为空就不说）。三种触发：① 空闲搭话：主人在电脑前（`perception/idle.py` 用 GetLastInputInfo 只读最后一次输入的时间戳，2 分钟内动过键鼠才算在）但 `idle_after_minutes` 内没和桌宠互动，两次之间至少隔各档的 `idle_repeat_seconds`；② 欢迎回来：系统空闲超过 `away_minutes` 后又有输入，3 分钟内找机会打招呼；③ 时间段问候：早上（5~10 点）、午饭（11~13）、晚饭（17~19）、深夜（23~2），每种每天一次，以凌晨 5 点为一天的分界，记录在 `%LOCALAPPDATA%/pet-kit/scheduler.json`（真正说出口才记；调用失败或模型选择不说，本次运行当天不再重试，重启后可以再试）。人不在电脑前时什么都不说。和看屏幕吐槽共用 `core/proactive.py` 的闸门（最小间隔、每小时上限、`screen.quiet_after_user_seconds`、调用失败退避 5 分钟），档位见 `core/screen_config.py` 的 `CHAT_CADENCES`；另外正在说话/思考/看屏幕、主人正在开口说话（VAD）、桌宠未连接、没指定聊天模型时都不搭话；免打扰比看屏幕吐槽更严（出声比气泡更打扰人）：前台全屏（幻灯片/游戏/视频，不受 `screen.allow_fullscreen` 影响）、任何可见窗口命中免打扰名单、前台窗口或窗口列表读不出来，都不说。前台是隐私黑名单窗口时照样可以搭话，但窗口名和标题不进事件和 prompt。发出前主人开口了，这句就不说。配置在 `config/backend.yaml` 的 `proactive` 段，控制台「感知」页「主动对话」卡片修改，状态里显示系统空闲时间和上一次主动搭话；一键全关也会关掉它。
- 技能（M8）：`config/skills.yaml` 是白名单（改完立即生效），代码在 `backend/action/skills/`（`config.py` 模型、`runner.py` 执行）。内置技能名只有 `open_app` / `play_music` / `open_game`；LLM 只给技能名和目标 id（或歌名），程序路径、URL、参数全来自 yaml，不在名单里的一律拒绝并记日志。只有用户对桌宠说话（`Agent.respond`：文字/语音/热键）时才在 prompt 里提供技能并解析 `tool_calls`（`parse_output(raw, labels, skills)` 丢弃未登记的名字，最多 3 个）；屏幕评论和主动搭话不提供技能，防止窗口内容/定时器触发操作。执行在后端（`api/app.py` 的 `emit` 之后另起任务，不挡对话）：`exe` 用 argv 启动（不经 shell），`url` 用 `os.startfile`。`confirm: true` 的技能先经 WS 弹窗：后端发 `confirm_request {id,title,detail}`，桌宠主进程用原生对话框（默认「拒绝」，关掉也算拒绝），回 `confirm_response {id,allow}`；无桌宠连接/超时（`confirm_timeout_seconds`）一律按拒绝。凭据：目标的 `credential` 指向 Windows 凭据管理器里服务名 `pet-kit/skill` 下的用户名，密码只在启动前替换 `args` 里的 `{secret}`，不进 prompt、日志、事件、气泡；注意命令行参数本机其他进程可见。失败时桌宠说一句固定的话（不含参数）。执行结果记入事件的 result.skills（控制台事件页可见）。`play_music` 默认只打开网易云（`orpheus://`）；按歌名搜索播放需要在 `search_url` 里配置能用的 URL，尚未在真机验证。
- 指令管理页与窗口自适应（M8 补充）：控制台「指令」页（`renderer/console/pages/SkillsPage.vue`）读写 `config/skills.yaml`，后端接口在 `api/skill_routes.py`：`GET/PUT /api/skills`（PUT 整体校验，失败 422 带可读原因）、`GET /api/skills/installed`（`action/skills/installed.py` 用 PowerShell 读开始菜单 .lnk，取指向 .exe 的快捷方式，去重并过滤卸载/帮助类，约 1-3 秒，按需调用）。「打开任意软件」仍走白名单：在页面里从已安装程序点选即可登记。桌宠窗口：模型用固定缩放（`scale` 为数字）时，渲染层用 `requiredWindowSize` 算出放得下模型的最小窗口，经 `pet:fit-window` 通知主进程；主进程把窗口设为「`frontend.yaml` 的 window 尺寸」与「所需尺寸」的较大者（上限 8000px），保持底边中心不动，位置夹进工作区；`scale: auto` 时回到配置尺寸。缩放上限统一为 10（配置与控制台一致）。
- 摄像头（M9，可选）：`config/backend.yaml` 的 `camera` 段，默认关。`perception/camera.py` 的 `CameraWatcher` 在开关打开时用 OpenCV（DirectShow）一直持有摄像头，每 `check_seconds` 秒抓一帧，本地 YuNet（`backend/models/camera/face_detection_yunet.onnx`，约 230KB，`scripts/fetch_models.py` 下载，不进 git）判断有没有人脸；`PresenceTracker` 去抖（连续 2 次有脸才算到场，`away_after_seconds` 秒没脸才算离开），发出 `camera.presence {state: "arrived"|"left", away_seconds?}`——事件里没有画面。画面只在内存里分析、立即丢弃，不落盘、不进日志。只有 `arrived` 且离开 ≥ `greet_min_away_minutes` 分钟、`greet_on_return` 开着时，`core/camera_react.py` 才依次检查：开关 → `proactive.enabled`（主动对话总开关关着就不打招呼；主人主动要求「看看我」和控制台「看一眼」不受影响）→ 有识图 LLM → 免打扰（所有可见窗口里有会议/录屏/直播）→ `core/proactive.py` 闸门（用 `proactive.mode` 的最小间隔和每小时上限，加 `screen.quiet_after_user_seconds`；和屏幕吐槽、主动对话共用预算）→ 抽一帧 JPEG（≤640px，内存）→ `Agent.respond_camera`（识图模型，`CAMERA_PROMPT`，不联网搜索，不评价长相、不认人），text 为空就保持安静；失败退避 5 分钟；看的过程中主人开口了就不说。会议/录屏软件运行时 `CameraWatcher` 会释放摄像头（不占着它），打开失败（被占用/没设备/缺模型）每 30 秒重试，原因显示在控制台。隐私提示：摄像头打开时后端通过 WS 推 `{"type":"camera","on":true,"present":true|false|null}`，桌宠窗口左上角显示「摄像头开启中 · 看到你了」（绿）/「· 没看到人」（红）；聊天回复的环境信息里会附带一行摄像头状态（`CameraWatcher.status_line()`，经 `Environment.extra_lines`）：关闭 / 没在工作 / 开着且检测到或没检测到人脸，并告诉模型它看不到画面细节、不要编造，所以问它「看得到我吗」时回答与真实检测结果一致。主人让它「看看我」时：摄像头在工作期间，聊天回合（仅主人主动说话时，不含主动搭话/看屏幕）会多提供一个内置动作 `look_camera`（`Agent.extra_tools`，登记在 skills.yaml 的内置动作里，见「内置动作登记」）；`api/tools.py` 的 `ToolRunner` 遇到它就发 `camera.presence {reason:"ask"}`，`CameraReactor._look_asked` 等桌宠说完「我看看～」后抽一帧交给识图模型（`CAMERA_ASK_PROMPT`，必须回应、如实描述），不受冷却和主动对话预算限制（主人在主动要求），免打扰仍生效；拿不到画面/看失败会给出提示气泡（断线时自动隐藏，因为此时后端也已不在看）；`POST /api/privacy/off`（托盘「关闭全部感知」/控制台左上角）同时关麦克风、屏幕感知、主动对话和摄像头。随手开关：模型右键菜单和托盘菜单里有「摄像头：已开启（点击关闭）/ 已启用但暂停中（点击关闭，比如在开会）/ 已关闭（点击开启）」（WS 的 camera 消息带 `enabled`，和实际打开状态分开），文字就是当前状态（托盘提示文字也会标注开启中）；也可在「快捷键」页启用内置动作 `toggle_camera`（默认 Ctrl+Alt+B，未启用）；三者都只是切换 `camera.enabled`，和控制台卡片是同一个开关。控制台「感知」页的摄像头卡片：设置、状态（是否打开、人在不在、错误、模型是否就绪）、「现在让它看一眼」（模拟刚回来，免打扰和忙碌仍生效）。接口：`GET/PUT /api/camera`、`POST /api/camera/look`。自测脚本：`uv run python scripts/camera_check.py [设备号]`（不保存画面）。
- 界面样式与自定义 CSS：`config/console.yaml`（`frontend/src/main/ui-config.ts` 校验，控制台「界面」页修改）除 `theme/accent/font_size` 外还有 `console_style`（default/round/sharp/warm，用 Naive UI 主题覆盖实现，见 `renderer/console/store.ts` 的 `consoleStyleOverrides`）、`input_style`（default/light/glass/outline/pixel）、`bubble_style`（default/dark/pink/glass/pixel）、`pet_css`、`console_css`（各最多 20000 字符）。预设清单在 `shared/ui-style.ts`；桌宠输入框/气泡的外观在 `renderer/pet-style.css`，用 `data-input-style` / `data-bubble-style`（桌宠窗口设在 `<html>` 上，控制台预览设在预览容器上）切换 CSS 变量（气泡 `--b-bg --b-fg --b-border --b-radius --b-shadow --b-blur`，输入框 `--i-bg --i-bg-active --i-fg --i-ph --i-border --i-radius --i-blur`），位置和尺寸仍在 `index.html`。自定义 CSS 以 `<style>` 注入各自窗口 `<head>` 末尾（桌宠：`#user-css`，控制台：`#console-css`），用 `textContent` 写入；窗口 CSP 的 `default-src 'self'` 挡住外链（`@import url(http…)`、远程图片）。预设选择器是 `[data-…] .pet-bubble`，所以自定义 CSS 要用 `#bubble` / `#chat-input` 才能盖过。保存后主进程 `onUiSaved` 经 `pet:style` 推给桌宠窗口，立即生效；启动时也从 console.yaml 读入（`RendererConfig.petStyle`），读取失败退回默认样式。
- LLM 备选轮换：`config/backend.yaml` 的 `llm.fallbacks.{chat,vision,memory}` 各是最多 2 个配置名（第二、第三顺位），校验在 `core/llm_config.py`（必须存在、不重复、不能与主用相同、没有主用就不能设备选）；`LlmConfig.chain(role)` 返回「主用 + 备选」列表，`memory` 没指定自己的配置时沿用聊天的链。聊天/识图（`Agent._converse`）和记忆总结（`core/memory/factory.py`）都走 `core/llm_chain.py` 的 `chat_with_fallback`：按顺序尝试，任何异常（超时、网络、HTTP 错误、创建客户端失败）就换下一个，全部失败才把最后一个错误告诉用户；联网搜索只对自己 `web_search` 不是 `off` 的配置开启（提示词里的搜索说明按主用算，备选不支持时模型可能提到搜索但实际没搜）。失败的配置按（用途, 配置名）进入 60 秒冷却（识图失败不会影响它在聊天链里的位置）：冷却期内排到链尾（不是跳过），避免主用挂了每句话都先等一个超时。冷却状态只在内存里，重启清空。日志里能看到「切换到备选配置 X」。控制台：「LLM」页的聊天/记忆、「识图」页的使用配置下面各有「第二顺位/第三顺位」下拉（`components/FallbackSelects.vue`）；`PUT /api/llm` 不带 `fallbacks` 时保留已存的值。「测试对话」仍只测所选的那一个配置，不走备选。
- 备选轮换的调用量：备选只在失败时才调用，主用成功不会多调一次；主用持续失败时有冷却，之后每次只有「备选成功」这一次调用；所有配置都挂了时每次主动搭话最多尝试 3 次，仍先过调度器的冷却和频率上限。
- 样式方案：`config/console.yaml` 的 `styles` 是一个列表，每项 `{name, console_style, input_style, bubble_style, pet_css, console_css}`，就是把当前五项外观存成一个有名字的快照（最多 30 个，名字 1~30 字、不能重名，字段校验同上，见 `ui-config.ts` 的 `readStyleFields`）。控制台「界面」页最下面的「样式方案」卡片：保存当前样式（同名覆盖）、应用（把五项写回当前设置）、删除；这三个操作都会立刻整页保存并推给桌宠，不需要再点上面的「保存」。方案不含主题/强调色/字号。
- 桌宠置顶：`frontend.yaml` 的 `window.always_on_top` 为 true 时（默认），`main/index.ts` 的 `keepOnTop` 把窗口设为 `screen-saver` 层级，并每 1.5 秒 `moveTop()` 一次（不激活窗口、不抢焦点），这样后打开的置顶窗口（浏览器、终端）也盖不住它。窗口隐藏时不处理。全屏独占的游戏/视频仍可能盖住它。
- 聊天记录清理与批量删除：控制台「聊天记录」页。① 「清理 / 删除 → 清理已总结的记录…」：只删 `summarized=1`（已提炼进长期记忆）的消息，保留最新的 N 条（默认 20，不管总结与否这 N 条都留着当上下文），没总结的一条都不会删；弹窗里实时显示将删除几条（`GET /api/history/summarized-count?keep_recent=N`），确认后 `POST /api/history/delete {summarized: true, keep_recent: N}`（不能和 ids/date/all 同用）。② 「多选」：每条消息前出现勾选框，点消息也能选，可「全选已加载的」，「删除所选」按 1000 个一批发 `{ids}`；只能选已经加载出来的消息（往上滚动会加载更多）。消息气泡下有「已总结」标签。③ 每次删除后（单条/按天/全部/清理）服务层 `MemoryService._after_delete` 会同步向量索引并对 `memory.db` 执行 `VACUUM`，否则 SQLite 文件不会变小；压缩失败只记警告。删聊天记录不影响长期记忆。
- 发图片给桌宠：在桌宠输入框里 Ctrl+V 粘贴图片，或把图片文件拖到桌宠窗口，输入框上方出现缩略图（点 × 或按 Esc 取消），再输入一句话回车发送；不输入文字时用默认提示「帮我看看这张图。有外文就翻译成中文……」。渲染层（`renderer/main.ts`）把图片重新编码成最长边 1600px 的 JPEG（去掉 EXIF，GIF/WebP 变静态）。WS 单条消息上限 64KB，且事件会进日志和控制台事件页，所以图片不走事件：主进程（`pet:send-image`）先用鉴权 HTTP `POST /api/pet/image`（`api/image_routes.py`，不在控制台白名单里）把图片存进后端内存（`core/image_stash.py`：最多 4 张、5MB、180 秒过期、取用一次即删、不落盘不进日志），再发 `user.text {text, image_id}`。`Dispatcher._ask_llm` 见到 `image_id` 就取图交给 `Agent.respond_image`：用识图用途（`roles.vision`，含备选）的配置，没指定识图时改用聊天配置；提示词 `IMAGE_PROMPT`；这一轮不提供技能/联网搜索；历史与记忆只存文字加「（附带一张图片）」。图片过期或丢失时桌宠说「这张图片已经过期了」，不调 LLM。所选配置必须支持图片输入（可在「识图」页测试）。
- 语气不被模型支持时的回退：MiniMax 对不同模型支持的语气不同（实测 `speech-2.8-turbo` 不支持 `whisper`，返回 2013「参数有误」，整句合成失败；`fluent` 未验证）。`action/tts.py` 的 `Speaker._run` 在拿到第一段音频前收到含 2013 的错误、且带了语气时，会去掉语气重试一次，并记住（模型, 语气）这个组合，之后同一模型不再尝试该语气；其他错误照旧报告。日志里会有「模型 X 不支持语气 Y，改用默认语气」。
- Live2D 动作文件头不对的问题：VTube Studio 导出的 `.motion3.json` 的 `Meta.CurveCount` 等可能和实际曲线数不一致（例如某个模型的 `sleep.motion3.json` 声明 9 条实际 6 条），Live2D 加载时会报 `Cannot read properties of undefined (reading 'Target')`，之后该动作一直无法播放，前端日志里有 `Failed to load motion`。需要把 `CurveCount / TotalSegmentCount / TotalPointCount` 改成实际数量（这些改动只做在导入到 `frontend/public/live2d/models/` 的副本上）。
- 映射文件夹名：`actionsConfigPath` 现在接受任何语言的文字（`\p{L}\p{N}`），与导入器生成文件夹名的规则一致；以前只认 ASCII，中文名模型会读不到映射和表情清单。

- 提示词可视化与知识库：控制台「提示词」页（`renderer/console/pages/PromptPage.vue`、`prompt.ts`），接口在 `backend/api/prompt_routes.py`：`GET/PUT /api/prompt`（读写 `config/prompt.yaml`，模型见 `core/prompt_config.py`，每回合重新读取）、`POST /api/prompt/preview {text}`（按已保存的设置拼出「如果现在说这句话」会发送的内容，不调用 LLM、不写记录）。系统提示词由 `Agent._assemble` 按段拼装（`Section{key,title,text,source}`），顺序：人设 → 时间和环境 → 记忆 → 知识库 → 联网搜索 → 当前情况（看屏幕/主动搭话等内置指令）→ 技能 → 表情和动作 → 输出格式（格式放最后，模型对末尾的要求遵守得最好）。`prompt.yaml`：`format_rules`（追加在输出格式后）、`knowledge`（`always` 每句都带 / `keyword` 用户这句话含关键词才带；合计最多 4000 字，超出的不发）、`expression_notes` / `motion_notes`（标签 → 什么时候用，显示为「happy（开心时）」）、`search_keywords`、`search_use_fallback`、`speech_repair`。`Agent.last_prompt` 保存最近一次真实发送的分段提示词、历史、模型原始回复（截断 4000 字）和错误，只在内存里，图片不保留；页面「上一次真实发送」读取它。知识库内容会原样发给模型，不要写凭据。

- 朗读语言补救（日语模式念中文的修复）：原因是模型漏写 `speech` 时 TTS 直接读中文 `text`，而且历史回放不带 `speech`，等于在示范「不写」。现在：① `messages` 表新增 `speech` 列（旧库首次打开时自动 `ALTER TABLE`），`history_message(m, with_speech)` 在朗读语言不是 `same` 时把历史回复的 `speech` 一并回放；② 输出格式里明确「speech 每次必须写且必须是该语言」；③ `speech_ok()` 检查（日语必须含假名，英语不能含汉字），不合格且 `prompt.speech_repair` 开着时，`Agent._repair_speech` 追加一次只做翻译的调用（走同一条配置链，不带历史和人设），仍失败才按气泡文字朗读并记警告日志。
